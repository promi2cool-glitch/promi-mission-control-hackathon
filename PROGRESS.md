## 2026-09-20 — [shipped] Independent Promi verifier (phase 7, O2/O3 achieved)

agent: claude-sonnet-5

Built `src/verifier/` as a deterministic rules/evidence engine — explicitly no LLM anywhere in the verdict path. `files.ts` implements dependency-free path safety (traversal, absolute-path, mixed-separator, duplicate-slash, and dot-segment bypass all handled via a stack-based segment resolver, plus a minimal `*`/`**` glob matcher); `permissions.ts` detects consequential-permission and forbidden-command violations from *observed* actions/commands only, never from mission goal text or worker prose, so a goal that merely mentions "deploy" can never trip a violation on its own; `tests.ts`/`definitionOfDone.ts` evaluate test-count evidence and free-text DoD items (labeling each item's evidence as objective vs. worker-reported, never conflating the two); `checks.ts` assembles 12 named `VerificationCheck`s; `verify.ts` aggregates them through an explicit priority ladder (documented inline) where a demonstrated contradiction (mission ID mismatch, an out-of-scope file, a forbidden action, canonical drift, failing regression tests) always outranks merely-missing evidence — so FAIL means "we can tell, and it's bad" and BLOCKED means "we can't tell," never confused with each other.

Ran `npm run verify:mission -- mis_demo_bugfix_001` for real against the actual completed mission from phase 5: **PASS**, all 12 checks green, verdict not hardcoded — it fell out of the evidence (independently-measured before/after test counts, file hashes, a live re-check that canonical `demo_project/` is still exactly 15 pass/1 fail). Then proved the verifier rejects bad work with 6 deterministic fixtures derived from that real result, no second live worker dispatched: (A) `worker_claim=COMPLETED` with `after.failed=1` → FAIL; (B) a `../private.txt` changed-file entry → FAIL (`changed_files_allowed`); (C) a synthetic observed `vercel deploy --prod` command against `demo/sample-forbidden-mission.json`'s `permissions.deploy=false` → FAIL, with a companion test confirming the goal text alone mentioning "deploy" does *not* trigger this; (D) zeroed-out test/session evidence → BLOCKED; (E) a mismatched `mission_id` → FAIL; (F) glowing worker prose ("Mission accomplished successfully") contradicted by real test failures → FAIL, proving prose is never trusted over measured evidence. 30/30 verifier unit tests pass (`npm run test:verifier`), 74/74 across the whole core suite. `scripts/verify.mjs` now also runs the real mission's verification and reports it as a distinct line (`VERIFICATION: PASS`) alongside core tests and the canonical demo baseline, still failing loudly if any of them regress. Generated `verification.json` and a plain-HTML `verification.html` (no framework) under the gitignored `.mission-runs/<mission-id>/`. O2 and O3 are now genuinely achieved — not just because a successful result happened to pass, but because the same engine was shown rejecting six different flavors of bad result first. Next: the Promi bridge (phase 8) and a demo UI.
